## Benchmarker

Measures how long pure JavaScript work takes inside Portal's QuickJS
runtime — useful for comparing implementations or finding a safe per-tick
iteration budget during development. Not intended for production code
paths; use it in isolated test mods or debug harnesses, then bake the
findings into your final design.

```ts
import { Benchmarker } from "bf6-portal-utils/benchmarker";

const totalMsA = Benchmarker.run(implementationA, 10_000);
const totalMsB = Benchmarker.run(implementationB, 10_000);
```

## Callback Handler

Safely invokes a sync or async callback: catches synchronous throws and
async rejections, logs them via a `Logging` instance, and does not rethrow.
Timers, Events, UI, Raycast, and Clocks all use it internally.

```ts
import { CallbackHandler } from "bf6-portal-utils/callback-handler";
import { Logging } from "bf6-portal-utils/logging";

const logging = new Logging("MyModule");

function tick(): void {
  CallbackHandler.invokeNoArgs(this._onTick, "onTick", logging, Logging.LogLevel.Error);
}
```

## Map Detector

Identifies the current map from Team 1's headquarters coordinates — a
workaround for `mod.IsCurrentMap`, which is unreliable.

```ts
import { Events } from "bf6-portal-utils/events";
import { MapDetector } from "bf6-portal-utils/map-detector";

Events.OnGameModeStarted.subscribe(() => {
  const map = MapDetector.currentMap();

  if (map == MapDetector.Map.Downtown) {
    // Downtown-specific logic
  }
});
```

## Multi-Click Detector

Detects when a player rapidly triggers a soldier state multiple times in
quick succession. Defaults to `mod.SoldierStateBool.IsInteracting`, which
pulses true for one tick even with nothing nearby to interact with — useful
for opening custom UI without a physical interaction point. Wiring to
`OngoingPlayer`, `OnPlayerDeployed`, `OnPlayerUndeploy`, and
`OnPlayerLeaveGame` is automatic through Events.

```ts
import { Events } from "bf6-portal-utils/events";
import { MultiClickDetector } from "bf6-portal-utils/multi-click-detector";

Events.OnPlayerJoinGame.subscribe((player: mod.Player) => {
  const playerId = mod.GetObjId(player);
  // create a detector for this player; event wiring is automatic
});
```

Callbacks can be sync or async; async is preferred, since a synchronous
callback blocks the entire `OngoingPlayer` stack for every player.

## Logging

The shared logging primitive that Timers, Clocks, Events, Map Detector, and
others use for their own `setLogging(...)` configuration calls. Most of the
time you'll pass a logger function to another module's `setLogging` rather
than instantiate `Logging` directly, unless you're writing your own module
on top of Callback Handler.

## The rest

`bf6-portal-utils` also includes Vectors (vector math), Raycast (raycasting
against the world), SolidUI (fine-grained reactive UI built on the UI
module), Sounds (pooled sound playback), Performance Stats (tick rate and
script lag metrics), Mod Extensions (typed helpers for undocumented `mod`
behavior), Portal Gadget, Player Undeploy Fixer, Scavenger Drop, and the
FFA Drop-ins / FFA Spawn Points pair. Each has its own README at
`node_modules/bf6-portal-utils/<module>/README.md` once installed — read
that directly for the current API, since these are less commonly reached
for than the modules covered on their own pages.
