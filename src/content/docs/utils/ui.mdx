`bf6-portal-utils/ui` wraps Portal's UI primitives in typed classes with
strongly typed helpers, ergonomic getters/setters, and automatic management
of scoped UI input mode. The module subscribes to `OnPlayerUIButtonEvent`
through the Events module at load time, so button events are dispatched
automatically.

```ts
import { Events } from "bf6-portal-utils/events";
import { UI } from "bf6-portal-utils/ui";
import { UIContainer } from "bf6-portal-utils/ui/components/container";
import { UITextButton } from "bf6-portal-utils/ui/components/text-button";

let testMenu: UIContainer | undefined;

// The UI module subscribes to OnPlayerUIButtonEvent via Events automatically.
// Use Events for your own game logic too.
Events.OnPlayerDeployed.subscribe((eventPlayer: mod.Player) => {
  if (!testMenu) {
    testMenu = new UIContainer({
      position: { x: 0, y: 0 },
      size: { width: 200, height: 300 },
      anchor: mod.UIAnchor.Center,
      receiver: eventPlayer,
      visible: true,
      uiInputModeWhenVisible: true,
      childrenParams: [
        {
          type: UITextButton,
          position: { x: 0, y: 0 },
          size: { width: 200, height: 50 },
          anchor: mod.UIAnchor.TopCenter,
          bgColor: UI.COLORS.GREY_25,
          baseColor: UI.COLORS.BLACK,
          onClickUp: (player: mod.Player) => {
            // sync or async; CallbackHandler catches errors either way
          },
          message: mod.Message(mod.stringkeys.ui.buttons.option1),
          textSize: 36,
          textColor: UI.COLORS.WHITE,
        } as UIContainer.ChildParams<UITextButton.Params>,
      ],
    });
  }
});
```

Key behaviors:

- **Automatic scoped input mode** — `uiInputModeWhenVisible: true` enables
  the input mode a visible container needs, and disables it again when the
  container is hidden, so players never get stuck unable to move because a
  menu was left open.
- **Components live at their own subpaths** — `UIContainer` comes from
  `bf6-portal-utils/ui/components/container`, `UITextButton` from
  `bf6-portal-utils/ui/components/text-button`, and so on. The bare `UI`
  import gives you the shared namespace (colors, anchors, constants), not
  the component classes themselves.
- **Button callbacks can be sync or async** — `onClickUp`, `onClickDown`,
  `onFocusIn`, and `onFocusOut` are all invoked through Callback Handler, so
  a throw or rejection inside one is caught and logged rather than crashing
  the rest of your UI.

:::caution
UI subscribes to `OnPlayerUIButtonEvent` through Events internally. Once you
use UI, all of your own event subscriptions must go through
`Events.OnX.subscribe(...)` as well — do not export competing `On*` handler
functions.
:::
