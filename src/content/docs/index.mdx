## Two packages, one SDK

The **Official Battlefield 6 Portal SDK** — the `mod` namespace and its
rule-block runtime — is EA/DICE's own product. This site documents it
through two independent, community-published TypeScript packages built
around that official SDK:

<CardGrid>
	<Card title="bf6-portal-mod-types" icon="seti:typescript">
		Type declarations mirroring the official runtime. Every type here is
		generated straight from the package's own `.d.ts` files — the
		[`mod` namespace](/reference/mod-types/bf6-portal-mod-types/namespaces/mod/),
		event handler signatures, enums, and interfaces for players, vehicles,
		and game mode objects.
	</Card>
	<Card title="bf6-portal-utils" icon="setting">
		The sister package that gets you moving faster: vector math, event
		plumbing, UI components, and state patterns built on top of the raw
		types. Authored by [deluca-mike](https://github.com/deluca-mike) and
		built to work seamlessly with `mod-types`, so you spend less time on
		boilerplate and more on your mode.
	</Card>
</CardGrid>

## Built for how people actually mod now

Whether you're hand-writing every line or steering a local LLM through your
first game mode, this site exists so what you generate actually compiles.
Every symbol on this site — every function, enum member, and event
signature — is extracted from the real, installed package, not recalled
from a model's memory or copied out of a forum post. That matters more,
not less, once AI tools enter the loop: an LLM asked to write Portal
scripts will confidently invent APIs that don't exist unless it's grounded
in something real. Point yours at this site's structured reference and
[`llms.txt`](/llms.txt) output, and it has ground truth to work from
instead of a guess.

## Ground truth, not tutorials

This site is generated directly from the installed `.d.ts` files with
[TypeDoc](https://typedoc.org/), not hand-copied from community guides. If
a symbol isn't in the reference, it isn't in the SDK — a distinction that
matters, since fabricated APIs (imagined `Network` or `Input` namespaces, a
`player.GetPosition()` that doesn't exist) circulate often enough in
unofficial write-ups and AI output alike to trip up a build.

That accuracy has one dependency worth naming plainly: this site tracks
whatever version of `bf6-portal-mod-types` and `bf6-portal-utils` is
currently installed (see the [About page](/about/) for details). If those
packages lag behind a Portal update, so will this reference — always
cross-check against the official DICE/EA documentation if something here
doesn't match what you see at runtime.
