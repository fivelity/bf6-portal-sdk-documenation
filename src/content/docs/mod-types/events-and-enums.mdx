## How Portal calls your code

The Portal runtime calls an exported function whenever its name matches a
known event — `OnPlayerDeployed`, `OnPlayerDied`, `OngoingPlayer`, and so
on. `bf6-portal-mod-types` supplies the exact parameter types for each.

```ts
// Signature shape, for illustration — see Events, Timers, and Clocks for
// the recommended way to actually subscribe in a real project.
declare function OnPlayerDeployed(eventPlayer: mod.Player): void;
```

:::caution
Only one function per event name can exist across your whole bundled
project. In practice, use `bf6-portal-utils/events` to subscribe instead of
exporting event functions directly — see
[Events, Timers, and Clocks](../../utils/events-timers-clocks/). That module
owns the actual exported handlers and lets multiple parts of your code
subscribe to the same event.
:::

## Reading enums

Enums are accessed the same way as any other `mod` member, with no import.

```ts
if (mod.GetSoldierState(player, mod.SoldierStateBool.IsAlive)) {
  // ...
}
```

## Building messages

`mod.Message` takes a template string with up to three `{}` interpolations:

```ts
const message = mod.Message("Player ID: {}", mod.GetObjectId(player));
mod.DisplayNotificationMessage(message, player);
```

For strings that should be localized, wrap literal text with your build
tool's string macro so it is extracted into `Strings.json` at build time
rather than sent as a raw literal.
