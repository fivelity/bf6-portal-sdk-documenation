This site is a **community-maintained documentation hub for the [Official
Battlefield 6 Portal SDK](https://portal.battlefield.com/)** — the
TypeScript scripting layer EA/DICE ships for building custom game modes on
Portal's rule-block runtime. Everything under **API Reference** is
generated by [TypeDoc](https://typedoc.org/) directly from the installed
`.d.ts` files, so what you read here is what `tsc` will actually accept —
not a hand-copied tutorial and not a model's best guess.

Two packages make up the SDK surface this site documents:

- **[`bf6-portal-mod-types`](https://www.npmjs.com/package/bf6-portal-mod-types)**
  — the type declarations for the official Portal runtime itself: the
  [`mod` namespace](/reference/mod-types/bf6-portal-mod-types/namespaces/mod/),
  `Events.On*` handler signatures, enums, and the interfaces that describe
  players, vehicles, and game mode state.
- **[`bf6-portal-utils`](https://www.npmjs.com/package/bf6-portal-utils)**
  — a helper layer built on top of the raw types: vector math, event
  subscription, timers, UI components, and other utilities that remove
  repetitive boilerplate from mode code. It's designed to work seamlessly
  alongside `mod-types`, and full credit for building and maintaining it
  goes to its author,
  [deluca-mike](https://github.com/deluca-mike).

## What "official" means here

The Portal **SDK itself** — the `mod` namespace, the runtime, the rule-block
system — is EA/DICE's official product. The **npm packages** this site
pulls from (`bf6-portal-mod-types` and `bf6-portal-utils`) are
community-published TypeScript definitions and helpers built around that
official SDK, not EA/DICE's own artifact. This site tracks whatever version
of those packages is currently installed (see the [About page](/about/) for
specifics) — if something here ever disagrees with what you see in-game,
treat the [official Portal documentation](https://portal.battlefield.com/)
as the tiebreaker.

That distinction matters more, not less, once AI tools enter the loop: an
LLM asked to write Portal scripts will confidently invent APIs that don't
exist unless it's grounded in something real. Every symbol on this site —
every function, enum, event handler, and type — is extracted from the
installed package, and the site ships a structured
[`llms.txt`](/llms.txt) so an agent has ground truth to work from instead
of hallucinating a `player.GetPosition()` that was never real.

## Who this is for

Right now, this documentation leans toward developers already comfortable
with TypeScript and Portal's rule-block model. That's a starting point, not
the ceiling — the goal is to grow this into a welcoming hub for **modders
of every skill level**, including PC gamers who have never written a line
of TypeScript but already have the hardware to run a local AI coding agent
and want help turning a game mode idea into a working mod. Planned
additions include quickstart guides for setting up a local LLM-backed
coding assistant on consumer GPU hardware, alongside the existing
engineer-focused reference.

Whichever path brought you here, this documentation assumes you want to
know, with certainty, what the SDK actually exposes — not what a tutorial
or forum post claims it exposes.

## How the docs are organized

1. **Getting Started** — install the packages, scaffold a project, and learn
   the small set of runtime concepts (single-owner event handlers, signals,
   ObjIds) that every mode relies on.
2. **bf6-portal-mod-types** — conceptual guides to the official type
   package: schemas, event handlers and enums, and the player/vehicle/game
   mode interfaces.
3. **bf6-portal-utils** — conceptual guides to the community helper
   package: logic helpers, vector math, event subscription, and state
   management.
4. **API Reference** — the full, auto-generated TypeDoc output for both
   packages, kept in sync with whatever version is pinned in `package.json`.

:::note
This site never hand-transcribes symbols. If you see a signature here, it
was extracted from the package's own type declarations at build time — see
the [About page](/about/) for exactly how, and for the version currently
tracked.
:::
